# Homewise Web App

React and TypeScript frontend for the household-budget and grocery-management API. Built with Vite and shadcn/ui using preset **bQEfFPsZc**: Base UI Maia, mist neutrals, cyan primary, Figtree body font, Inter headings and Hugeicons components. Theme tokens were generated by the shadcn CLI and retained.

## Prerequisites

Use Node.js 24 LTS, npm and Git. `.nvmrc` and `package.json` record the supported Node major version. The frontend can install, lint and build without an API checkout or a database. To use the application, start the companion Homewise API; it requires Windows, SQL Server 2022 and Microsoft ODBC Driver 17 for SQL Server.

## Run

```powershell
npm ci
npm run dev
```

Open [the local workspace](http://127.0.0.1:5173/). Start the API separately at port 4000; Vite proxies `/api` to `127.0.0.1:4000`. No API keys or database credentials belong in this repository.

The sidebar provides Overview, Budget and expenses, Kitchen inventory, Shopping lists, Products and prices, Store costs, Shopping plans, Purchases, Assistant and Settings. The layout adapts to narrower windows and provides labelled dialogs, validation messages, loading placeholders and explicit review before purchase confirmation.

## Build and contracts

```powershell
npm run check
```

`check` runs ESLint and the production TypeScript/Vite build. To refresh the contract types after an API change, run `npm run api:types` with the API checked out in the sibling `api` directory.

`api:types` consumes `../api/openapi.json` and generates `src/lib/api-schema.d.ts`. Generated types are checked in so an isolated app checkout can build. For checkouts in different locations, supply the copied contract path to `openapi-typescript`. There are no imports from backend source or Prisma code.

For example, with a contract copied to another directory:

```powershell
npx --no-install openapi-typescript C:/contracts/openapi.json -o src/lib/api-schema.d.ts
```

Detailed responses whose OpenAPI schemas remain open are described in `src/lib/models.ts`. Keep those read models aligned with API response changes.

`npm run preview` serves a production build, but does not provide Vite's development API proxy. Copy `.env.example` to `.env.local`, set `VITE_API_URL` to the API's origin (for example `http://127.0.0.1:4000`, without `/api/v1`) before building, and configure `APP_ORIGIN` in the API to match the preview URL. Use the same hostname for app and API so the API's SameSite=Strict refresh cookie works. Never put secrets in a `VITE_` variable; Vite embeds these values in the browser bundle.

## Verification

The production build and TypeScript checks run with `npm run build`. Budget, inventory, import, optimisation and purchase rules are tested in the independent `api` repository. Browser walkthroughs exercise the running app and its SQL-backed API.

Price data is fictional until you import permitted observations. Optional AI features report a configuration message until a backend model and credentials are supplied.

## Registration, sign-in and administration

The app opens on a sign-in/create-account screen. Registration creates a private household. The development build includes prefill shortcuts for administrator, Alice and Ben demo accounts. Access JWTs are held only in memory and renewed with a backend HttpOnly cookie; no JWT is written to localStorage. Signing out revokes the server session and clears the workspace.

Administration appears only for administrators, and the API enforces the same restriction. The panel manages names, roles, activation, password replacement and session revocation. Switching accounts remounts the household workspace so cached records cannot carry over.

## Repository maintenance

Commit the lockfile, `.env.example`, source and generated API types. Environment files, dependencies, build/test output and private keys are ignored. Run `npm audit` before a release; the GitHub Actions workflow checks installation, lint, build and dependencies without deploying.

The shadcn CLI is a development dependency. Its `@ts-morph/common` dependency has a scoped override to patched `minimatch` 11.x for [GHSA-g3hv-75wg-m249](https://github.com/advisories/GHSA-g3hv-75wg-m249). Review the override when updating shadcn; the CLI's path matching is checked locally as part of publishing preparation.

This is a local research prototype. Publishing source does not configure public hosting. Demo shortcuts only appear in development builds. An application licence has not been selected; dependency licences continue to apply to their respective packages.
